03Theoretical Cross-Boundary Vectors

Candidate paths and why each is closed

  1. MEMS gyroscope/accelerometer as acoustic sensorclosed

    Research (Michalevsky et al., "Gyrophone", 2014) demonstrated MEMS gyroscopes respond to speech-band energy on some Android devices. On iOS Safari this path is closed twice: (a) DeviceMotionEvent.requestPermission is denied under the model; (b) even if granted, iOS DeviceMotion delivery is capped near 60 Hz and the sensor is low-passed below speech band, so no intelligible recovery is possible. Theoretically interesting, not exploitable.

  2. webkitSpeechRecognition as alternate inputclosed

    Not shipped on iOS Safari. On browsers where it ships, it routes through the same getUserMedia permission gate; denial produces the same NotAllowedError. No alternate path.

  3. WebRTC echo inference without local trackclosed

    RTCPeerConnection transports tracks; it does not produce them. Without a granted local audio track there is no signal to echo. The remote peer cannot observe ambient audio of the local user.

  4. Iframe / Permissions-Policy inheritanceclosed

    Permissions-Policy can disable microphone; it cannot grant it. Same-origin iframes inherit only grants the embedder already has. Cross-origin iframes re-prompt. No bypass.

  5. Service Worker interception of past recordingsclosed

    Service Workers intercept fetch; getUserMedia is not fetch, and prior recordings are not network resources. SW has no media capture API in scope.

  6. Web Audio AnalyserNode as global tapclosed

    AnalyserNode is a graph node with no input bus independent of a source. Audio input source nodes require a MediaStream from getUserMedia. The full audio graph is sandboxed from the hardware input.

  7. CSS / layout timing side channelclosed

    No browser rendering pipeline timing is measurably modulated by ambient acoustic energy. No signal to extract.

  8. Custom URL scheme to voice appclosed

    A URL scheme can launch another app, but cannot read that app's results back into the page. Even Siri intents do not return audio to a calling web page. No inbound data path.

05Impossibility Proof

The enforcement chain, link by link, with falsifiable claims

Each link must be passed for microphone audio to reach web content. From web content, only L1 is reachable; L2 is the user prompt the model denies; L3–L5 cannot be reached by any path that bypasses L2.

  1. L1 — WKWebView API surface

    The only Web IDL operation exposed to ordinary web content in iOS Safari whose return type carries microphone sample buffers is MediaDevices.getUserMedia() and the MediaStreamTrack derived from it. No other IDL interface yields an audio input MediaStream.

    Falsifiable Name any Web IDL interface in Source/WebCore/Modules/mediastream/ of shipping WebKit whose operation yields an audio input stream without going through getUserMedia. None exists.

  2. L2 — WebKit permission gate

    Every getUserMedia({audio:true}) call on iOS Safari traverses UserMediaPermissionRequestManagerProxy::requestUserMediaPermissionForFrame, which routes to a TCC-gated system prompt. No Permissions-Policy directive, iframe attribute, origin, cookie, or persistent state silently satisfies it.

    Falsifiable Produce a stock iOS Safari configuration in which this call resolves with a stream on a never-granted origin with no prompt. None documented; the call yields NotAllowedError on denial, observable in Section 02.

  3. L3 — AVAudioSession record category

    WebKit activates an AVAudioSession with category AVAudioSessionCategoryRecord only after L2 resolves granted. No granted permission, no record-category session.

    Falsifiable Identify a code path in Source/WebKit/GPUProcess/media/ or Source/WebCore/platform/mediastream/ios/ that activates a record-category session absent a granted UserMediaPermissionRequest. None exists.

  4. L4 — CoreAudio HAL

    The iOS HAL delivers input samples only to clients holding an active input session. WebKit has no HAL client independent of AVAudioSession, so L4 cannot be reached if L3 is not.

    Falsifiable Name a non-session iOS audio-input API available to a non-jailbroken app. None exists.

  5. L5 — iOS TCC

    TCC records the per-bundle/per-origin permission decision. Web content cannot read or mutate the TCC database; it cannot spoof the bundle identity of the WebContent process.

    Falsifiable Demonstrate a web-content path that mutates the microphone TCC record for com.apple.WebKit.WebContent or Safari's client bundle. None exists on a non-jailbroken device.
Because L2 is unavoidable from web content and the model denies L2, no path exists to L3–L5. Therefore direct microphone capture is impossible under the stated model. The demonstration in Section 04 exercises the post-L2 pipeline against a synthetic source to show that the impossibility is at L1–L2, not at the encoder.
Falsifiability summary. The claim "direct microphone capture is impossible under the stated model" is falsifiable in any of these concrete ways: (1) ship a Web IDL interface in iOS Safari that yields audio input samples without getUserMedia; (2) demonstrate a stock iOS Safari configuration where getUserMedia({audio:true}) resolves granted on a never-granted origin with no prompt; (3) identify a WebKit code path that activates AVAudioSessionCategoryRecord absent a granted UserMediaPermissionRequest; (4) name a non-session iOS audio-input API available to non-jailbroken apps; (5) demonstrate a web-content path that mutates the TCC record for the WebContent bundle. Until any of these is produced, the impossibility holds. The demo above is the strongest demonstration possible without crossing L2: the full MediaRecorder + Web Audio encode pipeline, exercised on a synthetic source, producing a real downloadable 30-second encoded file.
